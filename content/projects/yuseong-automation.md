## 배경

- 유성구청은 분기별로 차상위 계층에게 종량제 봉투를 지급, 세대원 수에 따라 차등 분배
- 기존 업무 흐름
  1. 담당자가 지급자 명단 확인
  2. 주민 검색 프로그램에서 한 명씩 수작업 조회
  3. 세대원 수를 엑셀에 수기 기록
- 문제
  - 반복적인 단순 업무로 업무 효율 저하
  - 수기 입력으로 인한 오류 가능성
- 제약
  - 인트라넷 환경이라 외부 API · 개발자 도구 사용 불가
  - 주민 조회 프로그램에 직접 접근·연동 불가

## 결과

| 항목 | 결과 |
| --- | --- |

| 탐지율 | 실제 화면 기준 **40% → 100%** (100회 테스트 전건 탐지) |

## 해결 방식

### 1. 이미지 인식 기반 자동화 선택

- 화면을 직접 인식해 사람처럼 조작하는 매크로 방식 제안
- 판단 근거
  - 인트라넷 환경에서는 API 연동이 불가능해, 화면 자체를 입력으로 쓰는 방식만 가능
  - 공공기관 내부 서버 확보가 어렵고, 외부 클라우드는 지속적인 운영 비용과 예산 불확실성 존재
  - 외부 자원을 쓰면 내부망 통합·보안 절차에서 충돌 예상
  - 서버 구축 없이 바로 실행 가능한 응용 프로그램이 배포와 피드백에 가장 빠름

### 2. 목업 주민 조회 프로그램

- 실제 주민 조회 프로그램에 접근할 수 없어, 최소 기능만 재구현한 자체 조회 프로그램 개발
- 주민등록번호 조회 필드, 세대원 정보 검색 결과 화면 재현 (테스트 데이터는 생성형 AI로 생성)

### 3. 자동화 프로그램

- 입출력 파일 관리: CSV · Excel 원본 업로드, 출력 파일 이름·저장 경로 지정
- 진행률 표시 (엑셀 한 행 = 한 명 기준), 파일 처리 로그, 버튼 기반 동작 제어

[![목업 조회 프로그램과 템플릿 매칭 (클릭하면 원본)](/projects/yuseong-automation/develop.jpg)](/projects/yuseong-automation/develop.jpg)

### 4. 템플릿 매칭

- 화면에서 특징적인 UI 요소(조작 버튼, 입력 필드, 체크박스)를 템플릿으로 정의
- 뚜렷하고 고유한 UI 요소일수록 좋은 템플릿으로 선정
- 동작 흐름
  1. 프로그램에 템플릿 사전 등록
  2. OpenCV로 템플릿과 70% 이상 유사한 UI 요소 탐색
  3. PyAutoGUI로 등록한 이벤트를 순차 실행 (검색 필드 클릭 → 주민등록번호 입력 → 조회 → 체크박스 카운트·기록)

## 실제 환경 검증: 탐지율 40% → 100%

| 구분 | 내용 |
| --- | --- |
| 문제 | 목업에서는 동작했지만 실제 화면에서는 탐지율 40%. 화면 전체를 탐색하면서 팝업 밖의 유사한 UI를 잘못 찾고, 명암 차이로 실제 대상을 놓침 |
| 판단 | 임계값을 낮추면 오탐이 늘고 높이면 미탐이 늘어나, 값 조정만으로는 해결할 수 없는 구조 |
| 해결 | 탐색 범위를 다시 정의. 전처리 → 직선 검출 → 모달(팝업) 영역 추정 → ROI 추출·배경 마스킹 후, ROI 안에서만 템플릿 매칭 |
| 보완 | ROI 내부 특징 추출(Feature Detection), 명암 차이 보정 |
| 결과 | 배경 클릭 오탐 제거, 100회 테스트 전건 탐지 |
